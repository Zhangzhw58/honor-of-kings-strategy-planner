# ADR-0001：MVP 模型与端侧运行时

- 状态：已接受
- 日期：2026-08-18
- 决策范围：首个支持固定游戏 UI 版本的 Android MVP

## 背景

项目需要在 Android 中端设备上，以不高于 2 Hz 的频率从游戏画面提取小地图实体和游戏时间，并将端到端建议延迟控制在 5 秒以内。模型必须离线运行、可量化、可版本化，并允许识别失败时安全降级。

## 决策

1. Android 主推理运行时采用 **LiteRT**，MVP 只维护一个主运行时。
2. 小地图实体检测采用 **EfficientDet-Lite0，320×320 RGB，INT8 全整数量化**。训练初期可使用 FP32，发布资产为 `.tflite`。
3. 游戏时间不使用通用 OCR。固定 HUD ROI 经字符分割后，使用 **小型数字 CNN，32×32 灰度，INT8**，识别 `0-9` 与冒号；无法稳定分割时整项返回未知。
4. 布局定位、血条比例、技能冷却和资源图标首版使用模板匹配、颜色阈值或确定性规则，不建立独立深度模型。
5. 敌方位置首版采用 `last-seen + 地图邻接 + 时间衰减 + 规则先验` 的概率状态模型，不训练神经网络。
6. 战术决策首版采用 Kotlin 可组合规则，不使用学习模型直接生成行动或自然语言。

## 选择理由

- EfficientDet-Lite0 面向移动端检测，模型体积和计算量适合首版基准，LiteRT 的 Android 集成与整数模型支持直接。
- 小地图 ROI 尺寸小、图标密集，固定 320×320 输入便于建立统一标注和端侧预算。
- 游戏时间字体和位置固定，专用字符分类器比通用 OCR 依赖更小、输出更可控。
- 当前没有足够的连续、带真值轨迹数据训练敌方位置时序模型；概率规则模型更容易校验未知与置信度。
- 决策建议涉及安全与可解释性，端到端生成模型不适合 MVP。

## 后果

- 训练流水线必须能够导出 LiteRT INT8 模型，并使用具有代表性的校准集。
- Android 端模型输入输出以 `model-manifest.json` 为唯一解释依据，不硬编码标签顺序。
- 小地图检测训练数据采用 COCO 兼容 JSON；时间字符和未来序列数据使用版本化 JSONL。
- 真机基准若不满足 P95 1200 ms，可依次降低检测输入、减少类别、调整线程或评估其他 LiteRT 兼容模型；更换运行时需要新的 ADR。

## 暂缓方案

- ONNX Runtime Mobile：作为 LiteRT 无法支持关键算子或设备覆盖不足时的备选，不在 MVP 同时维护。
- YOLO 系列：不同实现的导出、许可证和后处理差异较大；获得统一数据集和真机基准后再评估。
- 通用 OCR/Tesseract：对固定数字 ROI 过重，且端侧依赖和波动更大。
- LSTM/Transformer 敌方轨迹预测：等待连续对局样本、事件时间线和可验证真值。

## 复审条件

- EfficientDet-Lite0 INT8 在目标中端设备上 P95 超过 1200 ms。
- 关键类别验证集召回率不能达到首版门槛。
- LiteRT 在首批支持设备出现不可接受的 delegate 或算子兼容问题。
- 已积累足够的按对局切分的连续轨迹数据，可对时序模型进行无泄漏评估。
