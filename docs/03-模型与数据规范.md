# 王者荣耀局势规划器：模型与数据规范

版本：0.1

更新时间：2026-08-18

状态：MVP 已确定基线

## 1. 模型职责边界

MVP 不使用一个模型直接理解整局并生成建议，而将感知、状态推断和决策分开：

| 能力 | MVP 实现 | 是否训练模型 |
| --- | --- | --- |
| 游戏布局与 ROI | 分辨率配置 + 锚点模板匹配 | 否 |
| 小地图实体识别 | EfficientDet-Lite0 INT8 | 是 |
| 游戏时间 | 字符分割 + 小型数字 CNN INT8 | 是 |
| 血量/技能/资源状态 | 颜色、模板和确定性规则 | 否 |
| 敌方可能位置 | 最后可见位置 + 地图转移 + 时间衰减 | 否，首版为概率状态模型 |
| 战术行动选择 | Kotlin 可解释规则 | 否 |
| 建议文本 | 本地模板 | 否 |

完整决策记录见 `docs/adr/0001-mvp-model-stack.md`。

## 2. 模型一：小地图实体检测

### 2.1 模型定义

- 架构：EfficientDet-Lite0。
- 运行时：LiteRT。
- 发布格式：全整数 INT8 `.tflite`。
- 输入：小地图 ROI，经 letterbox 到 `320 × 320`，RGB，`uint8`，张量布局 `NHWC`，batch 为 1。
- 输出：LiteRT Task Library 兼容检测结果，逻辑字段为边界框、类别索引、置信度和有效数量。
- 后处理：置信度过滤、NMS、letterbox 逆映射，再转换到原图坐标和归一化地图坐标。

发布前以导出模型的实际 tensor 名称和量化参数更新 `model-manifest.json`，Android 代码不得假设输出 tensor 顺序。

### 2.2 MVP 标签

标签表位于 `schemas/labels/minimap-v1.json`。首版只识别直接影响打野路线和风险的视觉类别：

- `self_hero`
- `ally_hero`
- `enemy_hero`
- `ally_tower`
- `enemy_tower`
- `neutral_objective`

不在检测标签中编码具体英雄身份、地图区域或敌方行为。英雄身份属于后续分类任务；地图区域由框中心坐标映射；行为由时序状态推断。

### 2.3 训练数据格式

检测数据采用 **COCO 兼容 JSON**，使用 `schemas/minimap-coco.schema.json` 校验，一个标注文件对应一个数据集版本：

```text
datasets/minimap/v1/
├── images/
│   ├── match_0001_000123.jpg
│   └── match_0001_000124.jpg
├── annotations/
│   ├── instances_train.json
│   ├── instances_val.json
│   └── instances_test.json
└── dataset-manifest.json
```

每张图片必须是已经裁剪的小地图 ROI，不是完整游戏截图。图片建议无损 PNG 或质量固定的 JPEG；文件中不得包含账号、聊天、系统通知等无关信息。

COCO 坐标规则：

- `bbox` 为 `[x_min, y_min, width, height]`，单位是 ROI 原始像素。
- 坐标原点在左上角，`x` 向右、`y` 向下。
- `category_id` 必须与标签表中的 `id` 完全一致，从 1 开始；0 保留给 background。
- `iscrowd` 固定为 0；遮挡严重且无法可靠标注的实体不创建伪框。
- `images[].id` 和 `annotations[].id` 在单个 JSON 中唯一且为正整数。

除标准 COCO 字段外，`images[]` 必须增加：

```json
{
  "id": 10123,
  "file_name": "match_0001_000123.jpg",
  "width": 256,
  "height": 256,
  "match_id": "match_0001",
  "frame_index": 123,
  "captured_at_ms": 61500,
  "game_time_sec": 61,
  "layout_profile": "hok-cn-v0.2-1920x1080",
  "source_id": "recording_0001"
}
```

自定义字段用于防止数据泄漏和支持分层评估；训练转换器可以忽略模型不需要的字段，但不能从源标注删除。

### 2.4 数据质量要求

- 按 `match_id` 分组切分 train/val/test，禁止逐帧随机切分。
- 同一原始录屏及其增强样本只能进入一个 split。
- 推荐初始比例为 70%/15%/15%，以对局数量而非图片数量计算。
- 空小地图帧必须保留并标注为零实例，用于控制误报。
- 每类至少覆盖不同地图区域、背景干扰、血量状态、分辨率和画质。
- 数据增强只作用于训练集；不得进行会破坏阵营或地图语义的随意水平/垂直翻转。
- 标注检查至少包含越界框、零面积框、未知类别、重复框和图片尺寸一致性。

### 2.5 首轮数据规模目标

首轮训练以覆盖度为目标，不把样本数量当作发布质量的替代指标：

- 至少采集 100 局彼此独立且已授权的对局，抽取约 8000～12000 张小地图 ROI。
- 空帧占比保持在 10%～20%，用于评估和抑制误报。
- `self_hero`、`ally_hero`、`enemy_hero` 每类争取不少于 3000 个实例。
- `ally_tower`、`enemy_tower` 每类争取不少于 1500 个实例。
- `neutral_objective` 争取不少于 1000 个实例，并覆盖未刷新、存活、争夺和消失前后的背景变化。
- test split 至少包含 15 局完整独立对局；若标签覆盖或分层指标不足，应继续采集而不是重复增强同一素材。

这些是启动目标而非充分条件，是否发布仍由第 7 节的独立测试集指标和真机性能决定。

## 3. 模型二：游戏时间字符识别

### 3.1 模型定义

- 架构：2～3 个卷积块的小型 CNN，最终输出 11 类 softmax。
- 运行时：LiteRT。
- 发布格式：INT8 `.tflite`。
- 输入：单字符灰度图 `32 × 32 × 1`，`uint8`，黑边居中填充，不拉伸字符比例。
- 标签：`0`～`9` 和 `colon`。
- 输出：长度 11 的校准后概率数组。

时间 ROI 首先通过固定布局裁剪和连通域分割得到字符。仅当字符数、冒号位置、分钟/秒范围和整体置信度均合法时，输出 `gameTimeSec`；否则返回未知。

### 3.2 字符数据格式

字符样本索引采用 JSONL，每行一个独立 JSON 对象，并使用 `schemas/time-character-sample.schema.json` 校验：

```json
{"schema_version":1,"sample_id":"tc_000001","image_path":"images/tc_000001.png","label":"7","match_id":"match_0001","source_id":"recording_0001","layout_profile":"hok-cn-v0.2-1920x1080","captured_at_ms":61500,"split":"train"}
```

规则：

- `image_path` 相对于 JSONL 所在数据集根目录，使用 `/` 分隔符。
- 图像必须为已经分割的单字符，不接受整段时间文本。
- split 同样按 `match_id` 分组生成；合成字符需使用独立 `source_id` 并限制在训练集。
- 保存原始字符裁剪，缩放和归一化由训练/推理共用的预处理实现完成。

首轮每个数字类别至少准备 1000 个真实字符样本，`colon` 至少 2000 个；覆盖首批支持的全部布局、分辨率、录制画质和明暗变化。合成样本只能补充训练集，不能替代真实验证集与测试集。

## 4. 敌方位置概率数据

MVP 不训练敌方位置神经网络，但从第一版开始记录可供未来训练的结构化序列。序列不得包含原始模型 tensor，而应包含稳定的领域状态。

首轮至少保留 50 局完整、按 1 秒步长重采样的结构化状态时间线，用于建立概率规则基线和验证序列 schema；在人工复核未来区域真值不足前，不启动时序神经网络训练。

### 4.1 地图区域标签

`MapRegion` 使用版本化枚举：

- `ally_red_zone`、`ally_blue_zone`
- `enemy_red_zone`、`enemy_blue_zone`
- `top_lane`、`mid_lane`、`bottom_lane`
- `top_river`、`bottom_river`
- `ally_base`、`enemy_base`
- `unknown`

后续增加区域时必须提升 schema 或标签版本，不得改变现有 ID 的含义。

### 4.2 未来训练序列格式

采用 JSONL，每行表示一个固定窗口样本，并使用 `schemas/position-sequence-sample.schema.json` 校验：

```json
{
  "schema_version": 1,
  "sample_id": "ps_match_0001_0060",
  "match_id": "match_0001",
  "hero_slot": "enemy_jungler",
  "step_ms": 1000,
  "history": [
    {
      "t_ms": 58000,
      "visible": true,
      "region": "top_river",
      "x_norm": 0.58,
      "y_norm": 0.31,
      "observation_confidence": 0.91
    },
    {
      "t_ms": 59000,
      "visible": false,
      "region": "unknown",
      "x_norm": null,
      "y_norm": null,
      "observation_confidence": 0.0
    }
  ],
  "target": {
    "horizon_ms": 5000,
    "region": "enemy_blue_zone"
  },
  "split": "train"
}
```

- `history` 必须按时间严格递增并重采样为固定 `step_ms`；缺失观测通过 `visible=false` 表达，不复制上一帧坐标。
- `x_norm`、`y_norm` 范围为 `[0,1]`，基于统一小地图坐标系。
- 训练目标来自未来真实可见位置或人工复核，不得使用待训练模型自己的预测作为真值。
- 同一 `match_id` 的所有序列只能属于一个 split。

## 5. 数据集清单

每个数据集版本必须包含 `dataset-manifest.json`，并使用 `schemas/dataset-manifest.schema.json` 校验。清单至少记录：

- 数据集 ID、语义版本、任务类型和 schema 版本。
- 创建时间、标签表版本和布局配置版本。
- train/val/test 的样本数和 `match_id` 数。
- 原始素材来源类别、许可说明和匿名化方式。
- 生成脚本的 Git 提交、随机种子和文件校验清单路径。

数据集内容存放在 Git 外部；Git 只提交 schema、标签、清单模板和小型合法测试样例。

可复制的最小示例位于 `schemas/examples/`。示例模型清单中的零哈希、零指标和 `TBD` 仅为占位符，不能作为发布清单使用。

## 6. 模型资产清单

每个发布模型旁必须包含 `model-manifest.json`，使用 `schemas/model-manifest.schema.json` 校验。关键字段包括：

- 模型 ID、版本、任务、文件名和 SHA-256。
- 格式、量化类型、运行时、输入/输出 tensor 契约。
- 标签文件及其 SHA-256。
- 训练数据版本、Git 提交、评估指标和校准方法。
- 最低应用版本、支持的布局配置和发布状态。

只有清单校验、文件哈希、schema 版本和布局版本全部匹配时，Android 才能加载模型。

## 7. 训练、评估与发布门槛

### 7.1 检测模型

首版候选发布门槛：

- 验证集 `mAP50 >= 0.75`。
- `enemy_hero` 和 `self_hero` 的 recall 均不低于 0.85。
- 空帧误报率不高于 5%。
- INT8 相对 FP32 的 `mAP50` 下降不超过 0.03。
- 目标中端设备单次检测 P95 不高于 1200 ms。

门槛是 MVP 基线，获得真实数据后可提高；不得为了达标改用泄漏的帧级随机切分。

### 7.2 时间字符模型

- 字符 macro F1 不低于 0.995。
- 完整时间解析准确率不低于 0.98。
- 非法或低置信度时间必须拒绝输出，单独报告拒绝率。

### 7.3 概率与阈值

- 模型置信度在验证集上进行温度缩放或适用的校准，不直接把 softmax/检测分数当业务置信度。
- 评估报告必须同时给出总体结果和按布局版本、分辨率、画质、类别的分层结果。
- 模型发布需要保存 FP32 基线、量化模型、代表性校准集版本和 Android 端输出一致性结果。

## 8. 数据目录约定

真实数据和模型不提交 Git，推荐本地/对象存储布局：

```text
data/
├── raw/                 # 原始授权录屏，只读
├── interim/             # 抽帧、ROI 和待审标注
├── processed/           # 版本化训练数据
└── manifests/           # 数据版本清单与哈希

artifacts/
├── training/            # checkpoint、日志、评估报告
└── release/             # .tflite、标签、model-manifest.json
```

原始数据到训练数据的每一步必须由脚本生成并可追溯，禁止人工覆盖 processed 数据后仍沿用旧版本号。

## 9. 后续模型升级条件

满足以下条件后再评估时序神经网络或其他检测器：

- 至少有按对局隔离的连续轨迹数据和人工复核的未来区域真值。
- 概率规则基线、评价指标和失败场景已经固定。
- 新模型在相同 test split 上显著优于基线，并满足端侧延迟和功耗预算。
- 模型许可证、导出链路和 Android 运行时兼容性已完成审查。
